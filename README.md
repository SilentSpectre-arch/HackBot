# 🛡️ HackBot — دستیار هوشمند تحلیل امنیت سایبری

**HackBot** یک برنامه‌ی دسکتاپ مبتنی بر پایتون است که با هدف ترکیب هوش مصنوعی محلی، تحلیل گزارش‌های امنیت شبکه و اجرای کنترل‌شده‌ی ابزارهای امنیتی توسعه داده می‌شود.

این پروژه از یک رابط گرافیکی برای ارتباط با مدل زبانی محلی، بررسی گزارش‌های Nmap، مقایسه‌ی نتایج اسکن‌ها و مدیریت اجرای اسکن‌های محدود و مجاز استفاده می‌کند.

هدف اصلی HackBot، ساده‌ترکردن برخی فعالیت‌های تکراری در ارزیابی امنیت، تحلیل داده‌های شبکه و خودکارسازی گردش‌کارهای امنیتی است.

> **وضعیت پروژه:** در حال توسعه  
> **سیستم‌عامل هدف:** Linux  
> **زبان برنامه‌نویسی:** Python

## 🎯 معرفی پروژه

در فرایند ارزیابی امنیت شبکه، متخصصان معمولاً با ابزارهای مختلفی برای شناسایی سرویس‌ها، بررسی پورت‌ها، تحلیل خروجی اسکن و مستندسازی نتایج کار می‌کنند.

HackBot با هدف جمع‌آوری بخشی از این فعالیت‌ها در یک محیط گرافیکی طراحی شده است.

این برنامه تلاش می‌کند سه بخش را در کنار یکدیگر قرار دهد:

1. **دستیار هوش مصنوعی محلی:** ارتباط با مدل زبانی از طریق Ollama.
2. **آزمایشگاه تحلیل امنیتی:** استخراج اطلاعات از گزارش‌های Nmap و مقایسه‌ی نتایج.
3. **ابزارهای امنیتی کنترل‌شده:** تعریف محدوده‌ی ارزیابی، اجرای پروفایل مشخص Nmap و ثبت تاریخچه‌ی اجراها.

HackBot یک پروژه‌ی آموزشی و کاربردی در حوزه‌ی امنیت سایبری و اتوماسیون امنیتی است و در حال حاضر جایگزین یک پلتفرم کامل تست نفوذ نیست.

## ✨ قابلیت‌ها

### 🤖 دستیار هوش مصنوعی محلی

- ارتباط با مدل‌های زبانی محلی از طریق Ollama
- ارسال پیام و دریافت پاسخ از مدل
- پشتیبانی از رابط گفت‌وگوی گرافیکی
- امکان استفاده از مدل محلی بدون نیاز ضروری به سرویس هوش مصنوعی ابری

### 🔍 آزمایشگاه تحلیل امنیتی

- بارگذاری گزارش‌های اسکن
- پردازش ساختاریافته‌ی خروجی XML ابزار Nmap
- استخراج اطلاعات میزبان، پورت، پروتکل و سرویس
- نمایش اطلاعات استخراج‌شده
- ارسال گزارش برای تحلیل با مدل زبانی محلی
- مقایسه‌ی دو گزارش و شناسایی تفاوت‌های موجود

### 🧰 ابزارهای امنیتی کنترل‌شده

- تعریف و مدیریت محدوده‌های شبکه
- بررسی قرارگرفتن هدف در محدوده‌ی ثبت‌شده
- پشتیبانی از یک پروفایل ثابت برای اسکن TCP
- نمایش دستور پیش از اجرا و دریافت تأیید کاربر
- اجرای Nmap از طریق `subprocess`
- مدیریت زمان اجرای فرایند
- ثبت تاریخچه‌ی اجراها و نتایج در SQLite

### 🗄️ مدیریت اطلاعات

- ذخیره‌ی محدوده‌های ثبت‌شده
- نگهداری تاریخچه‌ی اسکن‌ها
- ثبت وضعیت اجرا و کد خروج
- ذخیره‌ی خروجی و خطای فرایند برای بررسی‌های بعدی

## 🏗️ معماری پروژه

ساختار اصلی پروژه بر اساس جداسازی مسئولیت‌ها طراحی شده است.

```text
Hackbot/
├── main.py
├── security_lab.py
├── security_tools.py
├── requirements.txt
├── README.md
├── tests/
└── screenshots/
```

> ساختار بالا نمای پیشنهادی پروژه است. پوشه‌ها و فایل‌های `tests`، `screenshots` و `requirements.txt` باید در صورت نیاز ایجاد و تکمیل شوند.

### توضیح فایل‌ها

**`main.py`**

فایل اصلی برنامه که رابط گرافیکی، بخش گفت‌وگو با مدل و دسترسی به پنجره‌های دیگر را مدیریت می‌کند.

**`security_lab.py`**

ماژول آزمایشگاه تحلیل امنیتی که مسئول بارگذاری و پردازش گزارش‌ها، استخراج اطلاعات و مقایسه‌ی نتایج اسکن است.

**`security_tools.py`**

ماژول ابزارهای امنیتی که محدوده‌های ارزیابی را مدیریت می‌کند، هدف را اعتبارسنجی می‌کند، پروفایل تعریف‌شده‌ی Nmap را اجرا می‌کند و سوابق اجرا را ذخیره می‌کند.

**`requirements.txt`**

فهرست وابستگی‌های پایتونی مورد نیاز برای نصب پروژه.

**`tests/`**

محل پیشنهادی تست‌های خودکار برای بررسی صحت توابع و رفتار برنامه.

## ⚙️ پیش‌نیازها

پیش از اجرای پروژه، موارد زیر باید نصب و آماده باشند:

- Python 3
- pip
- Nmap
- Ollama
- حداقل یک مدل زبانی سازگار با Ollama
- کتابخانه‌ی PySide6
- کتابخانه‌ی Requests

برای بررسی نصب Python و Nmap:

```bash
python3 --version
nmap --version
```

برای بررسی Ollama:

```bash
ollama --version
ollama list
```

### نصب Nmap در Kali Linux

```bash
sudo apt update
sudo apt install nmap
```

### نصب Ollama

ابتدا Ollama را از منبع رسمی آن نصب کن:

https://ollama.com/

سپس مدل مورد نیاز را دریافت کن. برای مثال:

```bash
ollama pull llama3.2
```

مدل استفاده‌شده در پروژه باید با نامی که در تنظیمات برنامه انتخاب می‌شود مطابقت داشته باشد.

## 🚀 نصب و راه‌اندازی

### ۱. دریافت پروژه

اگر مخزن پروژه روی GitHub قرار دارد:

```bash
git clone https://github.com/SilentSpectre-arch/Hackbot.git
cd Hackbot
```

اگر نام مخزن تو متفاوت است، نشانی بالا را با نشانی واقعی مخزن جایگزین کن.

### ۲. ساخت محیط مجازی

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### ۳. نصب وابستگی‌ها

اگر فایل `requirements.txt` آماده است:

```bash
pip install -r requirements.txt
```

در غیر این صورت، وابستگی‌های مورد نیاز را نصب کن:

```bash
pip install PySide6 requests
```

### ۴. اجرای Ollama

اگر سرویس Ollama از قبل اجرا نشده است:

```bash
ollama serve
```

در یک ترمینال دیگر، در دسترس بودن API محلی را بررسی کن:

```bash
curl http://127.0.0.1:11434/api/tags
```

اگر پاسخ JSON حاوی فهرست مدل‌ها دریافت شد، سرویس API در دسترس است.

### ۵. اجرای برنامه

در مسیر اصلی پروژه:

```bash
python3 main.py
```

## 🖥️ نحوه‌ی استفاده

### ۱. استفاده از دستیار هوش مصنوعی

1. برنامه را اجرا کن.
2. مدل محلی مورد نظر را انتخاب کن.
3. پیام خود را وارد کن.
4. پاسخ مدل را در رابط گفت‌وگو بررسی کن.

این بخش می‌تواند برای توضیح مفاهیم امنیتی، بررسی خروجی ابزارها و کمک به مستندسازی استفاده شود.

### ۲. تحلیل گزارش امنیتی

1. پنجره‌ی آزمایشگاه تحلیل امنیتی را باز کن.
2. گزارش اسکن مجاز خود را بارگذاری کن.
3. اطلاعات استخراج‌شده را بررسی کن.
4. در صورت نیاز، قابلیت تحلیل گزارش را اجرا کن.
5. نتیجه‌ی تولیدشده توسط مدل را با گزارش اصلی تطبیق بده.

برای استخراج ساختاریافته‌ی اطلاعات، گزارش XML مناسب‌تر از خروجی متنی معمولی Nmap است.

### ۳. مقایسه‌ی گزارش‌ها

1. دو گزارش از ارزیابی‌های مجاز را انتخاب کن.
2. قابلیت مقایسه را اجرا کن.
3. تغییرات شناسایی‌شده را بررسی کن.
4. موارد جدید، حذف‌شده یا نیازمند بررسی بیشتر را مستند کن.

وجود یک تفاوت در گزارش به‌تنهایی اثبات‌کننده‌ی رفع یا ایجاد آسیب‌پذیری نیست.

### ۴. اجرای ابزارهای امنیتی

1. پنجره‌ی ابزارهای امنیتی کنترل‌شده را باز کن.
2. محدوده‌ی مجاز ارزیابی را ثبت کن.
3. یک هدف معتبر در همان محدوده وارد کن.
4. دستور و پروفایل اسکن را بررسی کن.
5. فقط در صورت داشتن مجوز، اجرای اسکن را تأیید کن.
6. خروجی و تاریخچه‌ی اجرا را بررسی کن.

**نکته:** ثبت یک محدوده در برنامه صرفاً یک کنترل نرم‌افزاری است و جایگزین مجوز واقعی برای ارزیابی هدف نمی‌شود.

## 🔐 ملاحظات امنیتی

امنیت خود ابزار نیز بخشی از طراحی HackBot است.

- اجرای اسکن باید به اهدافی محدود باشد که مجوز ارزیابی آن‌ها وجود دارد.
- هدف ورودی باید پیش از اجرا اعتبارسنجی شود.
- استفاده از پروفایل ثابت، سطح انعطاف‌پذیری اجرای فرمان‌ها را محدود می‌کند.
- اجرای فرایند باید بدون استفاده‌ی غیرضروری از shell انجام شود.
- برای عملیات طولانی باید محدودیت زمانی و مدیریت خطا در نظر گرفته شود.
- گزارش‌ها و سوابق اجرا ممکن است حاوی اطلاعات حساس باشند و باید به‌درستی محافظت شوند.
- خروجی مدل زبانی باید پیش از استفاده در تصمیم‌های امنیتی بررسی شود.
- محتوای گزارش نباید مستقیماً به فرمان اجرایی تبدیل شود.
- محدوده‌های ثبت‌شده در برنامه نباید به‌عنوان یک مرز امنیتی غیرقابل‌دورزدن در نظر گرفته شوند.

## ⚠️ محدودیت‌های فعلی

HackBot در حال توسعه است و محدودیت‌های زیر باید در نظر گرفته شوند:

- قابلیت اجرای اسکن در نسخه‌ی فعلی به یک پروفایل محدود Nmap متکی است.
- تحلیل هوش مصنوعی ممکن است نادرست یا ناقص باشد.
- مقایسه‌ی گزارش‌ها بر اساس داده‌های استخراج‌شده انجام می‌شود و به‌تنهایی وضعیت امنیتی یک سیستم را اثبات نمی‌کند.
- کنترل محدوده در سطح برنامه انجام می‌شود و به‌تنهایی کنترل دسترسی سیستم‌عامل نیست.
- پوشش تست‌های خودکار و ارزیابی امنیتی خود برنامه باید توسعه پیدا کند.
- قابلیت‌های پیشرفته‌ای مانند اسکن چندمرحله‌ای، مدیریت کامل یافته‌ها و تولید گزارش حرفه‌ای ممکن است هنوز پیاده‌سازی نشده باشند.
